## Управляющие скрипты (Python)

В корне каталога `_actions/` расположены центральные модули, координирующие работу всей системы.

### Структура папки

```text
[techlab-journal-attendance]
└── _actions/
    ├── journal-analyzer.py          # Модуль проверки комплектности отчетов.
    ├── journal-notify.py            # Модуль диспетчера буферного шлюза отчетов.
    └── journal_repair/ 
        ├── ja_repair_day.py         # Модуль нормализации название дня недели. 
        ├── ja_repair_delete.py      # Модуль удаления учеников из базы данных расписания. 
        ├── ja_repair_fields.py      # Модуль инспекции и чистки текстовых полей учащихся. 
        ├── ja_repair_modify.py      # Модуль модификации структуры расписания. 
        ├── ja_repair_space.py       # Модуль удаления лишних пробелов. 
        ├── ja_repair_structure.py   # Модуль контроля целостности и геометрии YAML. 
        ├── ja_repair_time.py        # Модуль форматирования синтаксиса времени групп. 
        ├── ja_session_manager.py    # Модуль контроля жизненного цикла сессий и статусов. 
        └── journal_repair.py        # Модуль проверки корректности записей расписания. 
```

*   **`journal-analyzer.py` (Модуль проверки комплектности отчетов)**
    *   **Назначение:** Проверяет, все ли группы преподавателя за конкретную дату прислали отчеты.
    *   **Логика работы:** Сопоставляет количество JSON-файлов в `_input/` со структурой занятий в YAML-расписании. Как только собран полный день, останавливает поиск и переносит всю группу файлов в папку `_output/`.

*   **`journal-notify.py` (Модуль диспетчера буферного шлюза отчетов)**
    *   **Назначение:** Обеспечивает безопасную передачу данных между двумя репозиториями.
    *   **Логика работы:** Работает в непрерывном цикле. Он вызывает анализатор, отправляет коммит с готовым комплектом в сеть, отправляет веб-сигнал на основной сайт через GitHub API и каждую минуту проверяет шлюз `_output`. Он ждет, пока внешний сайт заберет файлы и очистит папку, после чего переходит к следующему комплекту.
