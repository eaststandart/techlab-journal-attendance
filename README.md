# 📅 Система автоматизации и хранения данных Журнала посещений

Этот репозиторий выполняет роль изолированной базы данных и сервера автоматической обработки данных для Журнала посещений регулярных занятий в детско-юношеском клубе во Владивостоке. Проект развернут на платформе [Творческой лаборатории познавательного развития](https://eaststandart.github.io/).

### Зачем создан этот репозиторий

1. **Безопасность и разграничение прав:** Преподаватели имеют доступ на запись только в репозиторий `techlab-journal-attendance` для редактирования своего расписания и отправки отчетов. Доступ к основному репозиторию сайта (`eaststandart.github.io`) для них закрыт.
2. **Изоляция данных:** Исключена ситуация, когда случайное или ошибочное изменение кода сайта может нарушить работу базы данных расписания.

### Как это работает (Краткая логика системы)

Система построена на автоматических сценариях (GitHub Actions) и скриптах Python, которые обрабатывают два независимых потока данных:

1. **Поток отчетов (Режим Журнала):** Преподаватель отправляет отчеты с сайта в папку `_input`. Автоматика проверяет комплектность за день, собирает их в `_output` и сигнализирует сайту о готовности к публикации.
2. **Поток управления расписанием (Режим Ремонта):** При изменении данных на сайте формируется файл-сигнал в `_data`. Автоматика запускает конвейер очистки синтаксиса YAML, исправляет ошибки текста, выравнивает отступы и выполняет команды удаления или изменения данных учащихся.

*Примечание: Система защищена от конфликтов при одновременной работе нескольких преподавателей. Все запросы выстраиваются в строгую последовательную очередь.*

## ЧАСТЬ 1: Серверная автоматизация и база данных (`techlab-journal-attendance`)

В этой части описаны компоненты Журнала посещений, которые физически находятся в приватном репозитории данных. Они отвечают за безопасное хранение расписания в формате YAML, прием сырых JSON-отметок, построчную валидацию текста, исправление ошибок синтаксиса и автоматическое разрешение конфликтов при одновременной работе преподавателей.

### Структура репозитория

<pre>
[techlab-journal-attendance]
├── 📂 <a href=".github/workflows/">.github/workflows/</a>     # Сценарии запуска автоматизации (GitHub Actions)
├── 📂 <a href="_actions/">_actions/</a>              # Скрипты Python и подмодули конвейера ремонта базы
├── 📂 <a href="_data/">_data/</a>                 # YAML-база данных расписания и JSON-файлы статусов
├── 📁 _input/                # Буферная зона приема одиночных JSON-отчетов с сайта
└── 📁 _output/               # Выходной шлюз скомплектованных отчетов за учебный день
</pre>

#### Назначение директорий

*   **`.github/workflows/`** — Сценарии автоматизации GitHub Actions. Управляют запуском Python-скриптов при поступлении новых данных.
*   **`_actions/`** — Модули и скрипты на языке Python. Содержат всю логику проверки комплектности отчетов и исправления файлов расписания.
*   **`_data/`** — База данных расписания. Содержит файлы личного расписания преподавателей в формате YAML и файлы обмена статусами команд в формате JSON.
*   **`_input/`** — Буферная папка для приема сырых (одиночных) файлов посещений в формате JSON, поступающих с сайта.
*   **`_output/`** — Папка для скомплектованных отчетов за учебный день, готовых к отправке на основной сайт и последующей публикации.

### Назначение подсистем

*   **📂 [Конвейеры автоматизации](.github/workflows/README.md)** — Модули `journal-notify.yml` (обработка входящих отчетов) и `journal-repair.yml` (модерация базы расписания, проведение автоматических `git rebase` при конфликтах версий).
*   **📂 [Управляющие скрипты Python](_actions/README.md)** — Центральные диспетчеры `journal-analyzer.py`, `journal-notify.py`, `journal_repair.py` и 8 профильных подмодулей для точечного исправления текста, контроля геометрии YAML, удаления и модификации записей.
*   **📂 [База данных и сигналы](_data/README.md)** — Текстовые файлы личного расписания преподавателей (`.yml`) и сессионные файлы обмена состояниями с фронтендом сайта (`.json`).

## ЧАСТЬ 2: Клиентский интерфейс и генерация отчетов (`eaststandart.github.io`)

В этой части описаны компоненты Журнала посещений, которые физически находятся на стороне публичного репозитория сайта Лаборатории. Они отвечают за визуальный интерфейс, авторизацию преподавателей, отправку заполненных форм и финальную сборку отчетов.

### Структура папок и компонентов

<pre>
[eaststandart.github.io]

├── 📂 _actions/<a href="https://github.com/eaststandart/eaststandart.github.io/tree/main/_actions/journal_attendance">journal_attendance/</a>              # Каталог скриптов сборки отчетов и ботов
├── 📂 _includes/<a href="https://github.com/eaststandart/eaststandart.github.io/blob/main/_includes/journal-attendance.liquid">journal-attendance.liquid</a>       # Модуль шаблона интерфейса Журнала посещений
├── 📂 _pages/<a href="https://github.com/eaststandart/eaststandart.github.io/blob/main/_pages/journal-attendance.md">journal-attendance.md</a>              # Веб-страница Журнала посещений

    ├── 📂 css/<a href="https://github.com/eaststandart/eaststandart.github.io/blob/main/assets/css/journal-attendance.css">journal-attendance.css</a>            # Модуль стилей веб-страницы журнала посещений
    └── 📂 <a href="https://github.com/eaststandart/eaststandart.github.io/tree/main/assets/js">js/journal-attendance/</a>                # Каталог скриптов управления интерфейсом
</pre>

### Автоматизация и конвейеры (GitHub Actions)

*   **`journal-attendance.yml` (Модуль формирования Журнала посещений)**
    *   **Когда запускается:** Автоматически по внешнему сигналу `journal-notify` (событие `repository_dispatch`) из приватного репозитория данных.
    *   **Что делает:** Выполняет загрузку данных из изолированной базы, разворачивает Python-окружение и запускает главный управляющий конвейер сборки отчетов.

### Автономные подсистемы фронтенда и бэкенда

*   **📂 [Клиентские Java-скрипты](https://github.com/eaststandart/eaststandart.github.io/blob/main/assets/js/journal-attendance/README.md) (`assets/js/journal-attendance/`)**
    *   **Описание:** Изолированная папка с цепочкой из 7 JS-модулей без внешних зависимостей. Отвечает за проверку токенов, загрузку расписания, обработку текстовых команд модерации (`/d`, `/r`, `/m`), опрос статусов «ремонта» и валидацию полей ввода.
    *   *Подробная спецификация работы каждого JS-файла находится в локальном README внутри этой папки.*

*   **📂 [Скрипты генерации отчетов и боты](https://github.com/eaststandart/eaststandart.github.io/blob/main/_actions/journal_attendance/README.md) (`_actions/journal_attendance/`)**
    *   **Описание:** Автономная серверная подсистема на Python, координирующая публикацию результатов учебного дня и отправку уведомлений.
    *   *Подробная техническая документация логики парсинга, сборки Markdown-таблиц и рассылок находится в локальном README внутри этой папки.*

### Системные модули разметки и стилей

*   **`journal-attendance.md` (Веб-страница Журнала посещаемости)**
    *   **Назначение:** Точка входа для генератора страниц Jekyll. Содержит Front Matter метаданные адреса страницы (`/journal-attendance/`), вызывает модуль разметки `.liquid`, подключает индивидуальные стили и хранит встроенную текстовую инструкцию по генерации классических GitHub-токенов доступа для преподавателей.

*   **`journal-attendance.liquid` (Модуль шаблона интерфейса Журнала посещений)**
    *   **Назначение:** Динамическое построение HTML-структуры веб-страницы Журнала, генерация интерактивной формы авторизации по персональному токену, вывод сетки дней недели и регламента заполнения полей.

*   **`journal-attendance.css` (Модуль стилей веб-страницы журнала посещений)**
    *   **Назначение:** Модульное графическое оформление каскадных таблиц стилей, адаптивная геометрия чекбоксов, цветовая разметка активных дней недели, а также стилизация консоли починки времени и аварийных красных баннеров блокировки.
