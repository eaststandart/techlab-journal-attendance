# Система автоматизации и хранения данных Журнала посещаемости

Данный репозиторий выполняет роль изолированной базы данных и сервера автоматической обработки данных для Журнала посещаемости регулярных занятий в детско-юношеском клубе во Владивостоке.

### Зачем создан этот репозиторий

1. **Безопасность и разграничение прав:** Преподаватели имеют доступ на запись только в этот репозиторий для редактирования своего расписания и отправки отчетов. Доступ к основному репозиторию сайта (`eaststandart.github.io`) для них закрыт.
2. **Изоляция данных:** Исключена ситуация, когда случайное или ошибочное изменение кода сайта может нарушить работу базы данных расписания.

### Как это работает (Краткая логика системы)

Система построена на автоматических сценариях (GitHub Actions) и скриптах Python, которые обрабатывают два независимых потока данных:

1. **Поток отчетов (Режим Журнала):** Преподаватель отправляет отчеты с сайта. Они попадают в папку `_input`. Автоматика проверяет, все ли группы за день сдали отчеты, формирует полный комплект, переносит его в `_output` и передает сигнал на основной сайт для публикации.
2. **Поток управления расписанием (Режим Ремонта):** Когда преподаватель меняет расписание, удаляет ученика или редактирует время на сайте, формируется файл-сигнал. Автоматика запускает проверку синтаксиса YAML, исправляет ошибки в тексте, выравнивает отступы и выполняет команды удаления или изменения данных.

*Примечание: Система защищена от конфликтов при одновременной работе нескольких преподавателей. Все запросы выстраиваются в строгую последовательную очередь.*

## ЧАСТЬ 1: Серверная автоматизация и база данных (`techlab-journal-attendance`)

### Структура репозитория

```text
[techlab-journal-attendance]
├── .github/ 
│   └── workflows/          # Автоматизация и сценарии запуска
├── _actions/               # Скрипты проверки расписания
├── _data/                  # База данных расписания
├── _input/                 # Прием одиночных отчетов
└── _output/                # Готовые комплекты отчетов
```

### Назначение директорий

*   **`.github/workflows/`** — Сценарии автоматизации GitHub Actions. Управляют запуском Python-скриптов при поступлении новых данных.
*   **`_actions/`** — Модули и скрипты на языке Python. Содержат всю логику проверки комплектности отчетов и исправления файлов расписания.
*   **`_data/`** — База данных расписания. Содержит файлы личного расписания преподавателей в формате YAML и файлы обмена статусами команд в формате JSON.
*   **`_input/`** — Буферная папка для приема сырых (одиночных) файлов посещаемости в формате JSON, поступающих с сайта.
*   **`_output/`** — Папка для скомплектованных отчетов за учебный день, готовых к отправке на основной сайт и последующей публикации.

### Автоматизация и конвейеры (GitHub Actions)

В каталоге `.github/workflows/` находятся модули управления, которые автоматически запускают серверные проверки при изменении файлов в репозитории.

*   **`journal-notify.yml` (Модуль автоматизации отправки отчетов)**
    *   **Когда запускается:** Автоматически, как только в папку `_input/` добавляются новые JSON-файлы с отчетами посещаемости.
    *   **Что делает:** Блокирует параллельные запуски через диспетчер групп, чтобы отчеты обрабатывались строго по очереди. Вызывает главный Python-диспетчер шлюза для сборки комплекта.

*   **`journal-repair.yml` (Модуль исправления и обновления базы расписания)**
    *   **Когда запускается:** Когда преподаватель отправляет команду с сайта и в папке `_data/` появляется файл-сигнал вида `signal-repair-*.json`.
    *   **Что делает:** Запускает конвейер валидации текста расписания. В случае одновременного изменения данных несколькими людьми, модуль автоматически выполняет перебазирование (git rebase) и сам разрешает конфликты версий. Если происходит сбой — записывает лог ошибки в JSON-статус для сайта.

### Управляющие скрипты (Python)

В каталоге `_actions/` сосредоточена логика валидации отчетов и автоматического исправления базы данных расписания.

*   **`journal-analyzer.py` (Модуль проверки комплектности отчетов)**
    *   **Назначение:** Проверяет, все ли группы преподавателя за конкретную дату прислали отчеты.
    *   **Логика работы:** Сопоставляет количество JSON-файлов в `_input/` со структурой занятий в YAML-расписании. Как только собран полный день, останавливает поиск и переносит всю группу файлов в папку `_output/`.

*   **`journal-notify.py` (Модуль диспетчера буферного шлюза отчетов)**
    *   **Назначение:** Обеспечивает безопасную передачу данных между двумя репозиториями.
    *   **Логика работы:** Работает в непрерывном цикле. Он вызывает анализатор, отправляет коммит с готовым комплектом в сеть, отправляет веб-сигнал на основной сайт через GitHub API и контролирует шлюз `_output` до его полной очистки.

*   **`journal_repair.py` (Главный диспетчер исправления)**
    *   **Назначение:** Управляет последовательным конвейером очистки и модификации файлов расписания.
    *   **Логика работы:** Проверяет входящий JSON-сигнал, поочередно пропускает целевой YAML-файл через подмодули нормализации текста (`space`, `day`, `time`, `fields`), исправляет геометрию отступов через `structure`, а затем выполняет прямые команды удаления (`delete`) или изменения времени (`modify`).

*   **Линейные подмодули конвейера ремонта (`journal_repair/`):**
    *   `ja_repair_day.py` — Построчно находит названия дней и по внутреннему словарю синонимов приводит их к единому стандарту нижнего регистра.
    *   `ja_repair_space.py` — Выжигает пробелы в системном поле `tag` и схлопывает множественные пробелы в остальных строках YAML.
    *   `ja_repair_time.py` — Находит строки времени и преобразует любые некорректные текстовые разделители строго к каноническому формату `ЧЧ:ММ`.
    *   `ja_repair_fields.py` — Фильтрует текстовые поля учеников от мусора и автоматически раскрывает сокращения направлений (`э` -> `"электронное конструирование"`, `с` -> `"столярное дело"`).
    *   `ja_repair_structure.py` — Принудительно выравнивает геометрию отступов YAML по уровням вложенности расписания (0, 2, 4 и 6 пробелов).
    *   `ja_repair_delete.py` — Находит точные временные координаты группы и физически вырезает из файла указанные блоки строк учеников.
    *   `ja_repair_modify.py` — Изолирует целевой день недели в расписании и точечно заменяет строку старого времени группы на новое значение.
    *   `ja_session_manager.py` — Рассчитывает Unix-секунды коммитов Git для синхронизации и управляет записью файлов статусов.

### База данных и файлы обмена (`_data/`)

Каталог `_data/` выполняет роль распределенной плоской базы данных. Для каждого преподавателя в этой папке создается изолированная пара файлов, названная по его логину на GitHub.

#### Структура папки

```text
[techlab-journal-attendance]
└── _data/ 
    ├── journal-attendance-[логин GitHub].yml    # YAML-база расписания преподавателя
    └── repair-status-[логин GitHub].json        # JSON-файл обмена статусами команд
```

*   **`journal-attendance-[логин GitHub].yml` (Личный файл конфигурации и расписания)**
    *   **Назначение:** Хранение структуры занятий, времени групп и списков учащихся конкретного преподавателя.
    *   **Особенности:** Используется веб-интерфейсом Журнала для отображения календарной сетки на текущий день. Файл защищен от ручного редактирования третьими лицами и автоматически нормализуется конвейером при любых изменениях.

*   **`repair-status-[логин GitHub].json` (Файл фиксации состояний и обмена статусами)**
    *   **Назначение:** Передача сигналов между JavaScript веб-страницы Журнала и серверной автоматизацией GitHub Actions.
    *   **Логика работы:** Содержит текущую фазу работы конвейера (`status`: `"repair"`, `"off"`, `"error"`), маркер режима (`mode`) и точную метку времени. В случае синтаксических сбоев автоматика записывает в поле `errorDetails` подробный лог ошибки, который мгновенно выводится на «Красный экран» сайта для уведомления преподавателя.
