# Система автоматизации и хранения данных Журнала посещаемости

Данный репозиторий выполняет роль изолированной базы данных и сервера автоматической обработки данных для Журнала посещаемости регулярных занятий в детско-юношеском клубе во Владивостоке.

### Зачем создан этот репозиторий

1. **Безопасность и разграничение прав:** Преподаватели имеют доступ на запись только в этот репозиторий для редактирования своего расписания и отправки отчетов. Доступ к основному репозиторию сайта (`eaststandart.github.io`) для них закрыт.
2. **Изоляция данных:** Исключена ситуация, когда случайное или ошибочное изменение кода сайта может нарушить работу базы данных расписания.

### Как это работает (Краткая логика системы)

Система построена на автоматических сценариях (GitHub Actions) и скриптах Python, которые обрабатывают два независимых потока данных:

1. **Поток отчетов (Режим Журнала):** Преподаватель отправляет отчеты с сайта. Они попадают в папку `_input`. Автоматика проверяет, все ли группы за день сдали отчеты, формирует полный комплект, переносит его в `_output` и передает сигнал на основной сайт для публикации.
2. **Поток управления расписанием (Режим Ремонта):** Когда преподаватель меняет расписание, удаляет ученика или редактирует время на сайте, формируется файл-сигнал. Автоматика запускает проверку синтаксиса YAML, исправляет ошибки в тексте, выравнивает отступы и выполняет команды удаления или изменения данных.

### Структура репозитория

```text
[techlab-journal-attendance]
├── .github/ 
│   └── workflows/          # Автоматизация и сценарии запуска
├── _actions/               # Скрипты проверки расписания
├── _data/                  # База данных расписания
├── _input/                 # Прием одиночных отчетов
├── _output/                # Готовые комплекты отчетов
```

### Назначение директорий

*   **`.github/workflows/`** — Сценарии автоматизации GitHub Actions. Управляют запуском Python-скриптов при поступлении новых данных.
*   **`_actions/`** — Модули и скрипты на языке Python. Содержат всю логику проверки комплектности отчетов и исправления файлов расписания.
*   **`_data/`** — База данных расписания. Содержит файлы личного расписания преподавателей в формате YAML и файлы обмена статусами команд в формате JSON.
*   **`_input/`** — Буферная папка для приема сырых (одиночных) файлов посещаемости в формате JSON, поступающих с сайта.
*   **`_output/`** — Папка для скомплектованных отчетов за учебный день, готовых к отправке на основной сайт и последующей публикации.

### База данных и файлы обмена (`_data/`)

Каталог `_data/` выполняет роль распределенной плоской базы данных. Для каждого преподавателя в этой папке создается изолированная пара файлов, названная по его логину на GitHub.

#### Структура папки

```text
[techlab-journal-attendance]
└── _data/ 
    ├── journal-attendance-eastemitting.yml  # YAML-база расписания преподавателя
    ├── journal-attendance-techlab.yml        # YAML-база расписания администратора
    └── repair-status-eastemitting.json      # JSON-файл обмена статусами команд
```

*   **`journal-attendance-[логин GitHub].yml` (Личный файл конфигурации и расписания)**
    *   **Назначение:** Хранение структуры занятий, времени групп и списков учащихся конкретного преподавателя.
    *   **Особенности:** Используется веб-интерфейсом Журнала для отображения календарной сетки на текущий день. Файл защищен от ручного редактирования третьими лицами и автоматически нормализуется конвейером при любых изменениях.

*   **`repair-status-[логин GitHub].json` (Файл фиксации состояний и обмена статусами)**
    *   **Назначение:** Передача сигналов между JavaScript веб-страницы Журнала и серверной автоматизацией GitHub Actions.
    *   **Логика работы:** Содержит текущую фазу работы конвейера (`status`: `"repair"`, `"off"`, `"error"`), маркер режима (`mode`) и точную метку времени. В случае синтаксических сбоев автоматика записывает в поле `errorDetails` подробный лог ошибки, который мгновенно выводится на «Красный экран» сайта для уведомления преподавателя.
