# Система автоматизации и хранения данных Журнала посещаемости

Данный репозиторий выполняет роль изолированной базы данных и сервера автоматической обработки данных для Журнала посещаемости регулярных занятий в детско-юношеском клубе во Владивостоке.

### Зачем создан этот репозиторий

1. **Безопасность и разграничение прав:** Преподаватели имеют доступ на запись только в этот репозиторий для редактирования своего расписания и отправки отчетов. Доступ к основному репозиторию сайта (`eaststandart.github.io`) для них закрыт.
2. **Изоляция данных:** Исключена ситуация, когда случайное или ошибочное изменение кода сайта может нарушить работу базы данных расписания.

### Как это работает (Краткая логика системы)

Система построена на автоматических сценариях (GitHub Actions) и скриптах Python, которые обрабатывают два независимых потока данных:

1. **Поток отчетов (Режим Журнала):** Преподаватель отправляет отчеты с сайта в папку `_input`. Автоматика проверяет комплектность за день, собирает их в `_output` и сигнализирует сайту о готовности к публикации.
2. **Поток управления расписанием (Режим Ремонта):** При изменении данных на сайте формируется файл-сигнал в `_data`. Автоматика запускает конвейер очистки синтаксиса YAML, исправляет ошибки текста, выравнивает отступы и выполняет команды удаления или изменения данных учащихся.

*Примечание: Система защищена от конфликтов при одновременной работе нескольких преподавателей. Все запросы выстраиваются в строгую последовательную очередь.*

#### Назначение директорий

*   **`.github/workflows/`** — Сценарии автоматизации GitHub Actions. Управляют запуском Python-скриптов при поступлении новых данных.
*   **`_actions/`** — Модули и скрипты на языке Python. Содержат всю логику проверки комплектности отчетов и исправления файлов расписания.
*   **`_data/`** — База данных расписания. Содержит файлы личного расписания преподавателей в формате YAML и файлы обмена статусами команд в формате JSON.
*   **`_input/`** — Буферная папка для приема сырых (одиночных) файлов посещаемости в формате JSON, поступающих с сайта.
*   **`_output/`** — Папка для скомплектованных отчетов за учебный день, готовых к отправке на основной сайт и последующей публикации.

### Назначение подсистем

*   **📂 [Конвейеры автоматизации](.github/workflows/README.md)** — Модули `journal-notify.yml` (обработка входящих отчетов) и `journal-repair.yml` (модерация базы расписания, проведение автоматических `git rebase` при конфликтах версий).
*   **📂 [Управляющие скрипты Python](_actions/README.md)** — Центральные диспетчеры `journal-analyzer.py`, `journal-notify.py`, `journal_repair.py` и 8 профильных подмодулей для точечного исправления текста, контроля геометрии YAML, удаления и модификации записей.
*   **📂 [База данных и сигналы](_data/README.md)** — Текстовые файлы личного расписания преподавателей (`.yml`) и сессионные файлы обмена состояниями с фронтендом сайта (`.json`).
